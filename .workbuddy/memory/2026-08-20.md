# 2026-08-20 工作日志

## 用户管理：新增用户页面不显示
- 现象：插入用户后 DB 有数据但列表不显示。日志中列表 SQL 过滤条件为 `del_flag='0' AND dept_id IN(...) AND tenant_id='000000' ORDER BY user_id ASC LIMIT 10`。
- 排查方向：① 分页（user_id 升序，新用户 id 最大被排到最后一页）；② del_flag 非 '0'（NULL 最常见）；③ tenant_id 非 '000000'；④ dept_id 不在当前登录人数据权限范围内。
- 根因（本次确认）：PostgreSQL 建表脚本 `script/sql/postgres/ruoyi_vue_pgsql.sql` 中 `del_flag` 列缺少 `DEFAULT '0'`，导致插入未显式赋值的新用户 del_flag 为 NULL，被 `del_flag='0'` 过滤。
- 修复：已将 7 张表的 `"del_flag" character(1),` 改为 `"del_flag" character(1) DEFAULT '0',`（sys_client/sys_dept/sys_role/sys_social/sys_tenant/sys_tenant_package/sys_user）。
- 注意：DEFAULT 只对新建行生效；已有 NULL 行需手动 `UPDATE sys_user SET del_flag='0' WHERE del_flag IS NULL;`（视情况扩展到其他表）。

## 角色新增报错：column menu_check_strictly is of type smallint but expression is of type boolean
- 报错位置：SysRoleMapper.insert，PostgreSQL 报 `menu_check_strictly` smallint 与传入的 boolean 不匹配。
- 原因：PostgreSQL 的 `smallint` 不能隐式接收 Java `Boolean`（MyBatis 绑定为 boolean）；MySQL 的 `tinyint(1)` 可以，所以只在 PG 报错。
- 修复（不影响 MySQL、不改 Java/前端）：在 `script/sql/postgres/ruoyi_vue_pgsql.sql` 中将以下 3 个 Postgres 列类型由 `smallint` 改为 `boolean`：
  - sys_role.menu_check_strictly、sys_role.dept_check_strictly
  - sys_tenant_package.menu_check_strictly
- 运行中的库需执行 ALTER（带 USING 转换现有 0/1）：
  `ALTER TABLE sys_role ALTER COLUMN menu_check_strictly TYPE boolean USING (menu_check_strictly <> 0);` 等同理处理 dept_check_strictly、sys_tenant_package.menu_check_strictly。
- 说明：Java 实体字段为 Boolean，MySQL(tinyint(1)) 与 PG(boolean) 均能正确映射，无需改实体/前端。
